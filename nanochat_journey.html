Scaling Laws: The Brain Behind the Training Decisions

Scaling laws determine how long to train, how big the batches should be, and how fast to learn. Instead of guessing, nanochat uses math derived from research papers to auto-calculate optimal settings for any model size. Everything is anchored to a reference model (d12) and scaled up using principled formulas.

1. Training Horizon (How many tokens?)

tokens = data_ratio × scaling_params

Chinchilla (2022) showed optimal ratio is ~20. Karpathy experimented and found ratio=8 is enough to beat GPT-2 (slightly undertrained but faster). Changed from 20→8 in Jan 2026, then 8→12 in Mar 2026 after more scaling law runs.

2. Batch Size (How many tokens per step?)

B_opt ∝ D^0.383 (Power Lines paper)

Originally fixed at 524K tokens for all models. Discovery: d26 needs 1M tokens per batch, not 512K. Auto-calculating this gave a free 5% speedup (leaderboard #3). Clamped to nearest power of 2 for GPU efficiency.

3. Learning Rate Scaling

η ∝ √(B / B_ref) × (dim / 768)^-0.5

Two scaling factors: sqrt batch size scaling (standard AdamW theory) + muP-style 1/√width scaling. Tuned at d12 reference, automatically transfers to d24/d26. Applied blindly to Muon optimizer too — "hoping it works" (it does).

4. Weight Decay Scaling

λ = λ_ref × √(B/B_ref) × (D_ref/D)

From T_epoch framework (2024 paper). Keeps regularization strength consistent across model sizes. Earlier: found empirical law WD ∝ 1/channels². Later replaced with this more principled formula. Cosine-decayed to zero during training.

The Scaling Laws Workflow

1. Train many small models (d10–d20) at multiple compute budgets (1e18 to 1e19 FLOPs)
2. Plot loss vs. FLOPs for each model size — find the "frontier" (best loss per FLOP)
3. Fit power laws to predict optimal settings for larger models (d24–d26)
4. Use d12 as reference point — all hyperparameters tuned there, then transferred via formulas
5. The single dial is --depth — everything else auto-calculates from it
